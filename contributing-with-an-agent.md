# Contributing with a coding agent



Open this repo in the agent, point it at this file and [README.md](README.md), then describe the weapon or behaviour you want. You do not need to paste the rules into chat — the agent should read them here.

Before opening a pull request, follow [docs/pull-request-code-of-conduct.md](docs/pull-request-code-of-conduct.md): keep `main` current, resolve conflicts on your branch, prefer one feature per PR, and treat [`.github/workflows/rust.yml`](.github/workflows/rust.yml) as the build gate (required for non-Windows contributors).

New power is a **Lua pack** or one **verb**. Not a dump of `WA.exe` into scripts.

Ghidra and Ghidra MCP might be required if user wants to attempt out-of-the-box implementations, this needs manual setup, inform user/author if it's needed and guide him through installation. But do not assume it is required, most of the RE is available.

## Packs

A pack is a folder (`mod.toml` + Lua + optional sprites/sounds). Copy it to `Mods/` next to `WA.exe`. No compiler.

```
mods/examples/my_thing/
  mod.toml
  weapons.lua          (or init.lua)
  sprites/…
  sounds/…
```

v1 overlays a stock panel slot. It cannot add a 72nd icon. Several packs may overlay the same slot: they all load; **first loaded `id` keeps the slot**, later claims for that slot are skipped. `gif_donkey` and `gif_donkey_lua` both overlay grenade on purpose — statuses vs a Lua brain — and that skip is the system working. You can also call weapons arbitrarily without them existing at all in panel/scheme, see q_bazooka example in /mods.

The engine (`crates/`, `wkLua.dll`) is only for verbs Lua cannot call yet. Prefer a pack.

Needs: WA **3.8.1** + WormKit, this repo, `wkLua.dll` next to `WA.exe`. Test in a match; logs are `wkLua.log` and `wkluaerror.txt`, both beside `WA.exe`. Then open a PR — only after [docs/pull-request-code-of-conduct.md](docs/pull-request-code-of-conduct.md).

| You want… | Start from |
|---|---|
| Log a line, no weapon | `hello` |
| Same bazooka, new sprite / gravity / wind | `circle_bazooka` |
| Click the map, a body falls and explodes | `gif_donkey_lua` (Lua) or `gif_donkey` (statuses) |
| Cut-in, extra sprites, sounds on fire | `wormcraft` |
| Click a worm, drag, throw | `worm_toss` |
| Selecting the slot *is* a mini-game | `pooz` |
| Hotkey that stock-selects an existing gun | `q_bazooka` |
| Hurt layer (`worm:hurt` + `wa.on.hurt`) | `hurt_lab` |
| Hitscan sentry (`a:frame`, `land.trace`, `worm:hurt`) | `turret` |

## Pack contract

Lua sees `wa` and handles (`a`, `worm`). Not C++ names, not `unknownC`, not pointers.

A weapon is usually a **LuaActor**: `wa.weapons.replace` then `on_click` / `on_fire` spawn a body with a brain. An `on_click` event has `worm`, `x`, `y` (the click, from WA's fire context), `sky`, `slot` and `vx`, `vy`: the shot's speed in that context, 16.16 (0 when the click is eaten before WA fires, as with `eat_fire`); for a strike the sign of `vx` is the direction WA's arrow keys set, as Project X's airstrikes read it (0 or more: from the left). Status tables (`gravity = true`, …) are the GUI path (`gif_donkey`). Overlay a stock missile (`params`, `wa.on.gravity_*`) only when you still want stock flight (`circle_bazooka`).

- Positions / speeds are WA **16.16** integers (`0x10000` = 1 pixel).
- Space is shoot (hold to charge bazooka-type, release to fire). Enter / Backspace are `wa.msg.JUMP` / `JUMP_UP`. `wa.world.keys().jump` is W (POOZ), not Space.
- `wa.world.keys().ctrl` is synchronized Ctrl. `stock_fire_choice = { held = "ctrl", alternate = "surrender" }` on a weapon claim uses its normal stock fire unless Ctrl is held, then fires a pristine stock Surrender record through the existing dispatch. On the Skip Go slot, Ctrl also shows the stock Surrender armed and fire sprites while held. The choice affects only that claim.
- Sim on messages both peers already see. HUD does not write physics: the engine refuses it. Every write that reaches the simulation (a worm's or actor's `x y vx vy`, `facing` `fuel` `gravity` `wind` `collision_mask` `visible` `body_visible`, `carry` `drop` `take` `release` `jetpack_steer` `equip` `hurt`, an ammo change, `wa.actors.spawn`, `a:explode` / `a:despawn`, and the older sim-only verbs) errors outside a simulation callback, and `wa.random` errors in `wa.on.draw` and `wa.on.hud`. `keys()` / `pointer()` are synchronized in networked games: every peer reads the input of the player whose turn it is (the other player's keys never steer it); every peer must run the same WormForge build.
- No `math.random`, no clock, no filesystem from Lua. Assets stay inside the pack.
- Iterate a table's keys with `wa.sorted(t)` when the order reaches the sim: `for _, k in ipairs(wa.sorted(t)) do ... t[k] ... end`. Plain `pairs()` order over string-keyed tables differs per process — keys that are actor/worm `id`s are fine, they are integers.
- `api_version = 1`. Renaming the Lua API is a breaking change: bump it.

`register` does not add a panel row; it still occupies `based_on`.

`wa.on.hurt` runs on blast / hit / percent / nonlethal / poison (both peers). `percent` is axe-style: `amount` is 50 meaning half current HP. `pre` may write `amount` or return `"eat"`. `post` has `lost` (HP that actually left). `worm:hurt(10)` posts stock hit (0x4B) with no knockback; pending HP still waits until momentum ends. `worm:ammo("mine")` reads team ammo; `worm:ammo("mine", 1)` adds, and leaves infinite (`-1`) alone; `worm:ammo("mine", { set = 1 })` sets it outright, overwriting infinite too (`set = -1` makes it infinite). `worm.alliance` is WA's visible coalition colour (0 red .. 5 cyan); `worm.ammo_group` is its separate physical ammo row. Granting keeps the weapon in its own panel row.
For a stock arrow hit, `wa.on.hurt` supplies `hit.source_weapon`: the stock slot
that created the arrow, such as `"armageddon"`. Other sources leave it nil.
`worm:freeze()` enters WA's frozen state from a simulation callback and returns
true when a living worm changes state; WA handles its frozen pose and thaw.

Per-worm loadouts are virtual because WA has no per-worm ammo row. `wa.inventory.create({ id = "classes", slots = {...} })` creates a store scoped to the registering pack. It supports `get`, `set`, `add`, `remove`, `clear`, `list`, deterministic `deal`, `transfer`, and `apply`. `apply(worm, { clear = true, each = 1 })` clears the store's slots on every live ammo row and materializes only that worm's inventory. `transfer(from, to, { weapons = "all", amount = n, mode = "move"|"copy" })` takes explicit worm targets; put conditions in normal Lua callbacks.

`panel_icon = "sprites/icon.png"` on `replace` puts a pack PNG in the stock weapon panel: 32×32 (WA's and every PX icon's full size; the panel shows the centre 24×24) or up to 24×24, quantized to WA's icon colours with an automatic greyed frame. `panel_icon = "banana"` still borrows a stock icon. See `docs/weapon-panel.md`.

`hold = { sheet = "sprites/weapon", hand = "sprites/hand", weap_radius = 9 }` on `replace` draws a GPU sheet over the worm's aim pose. The engine follows WA's live aim and facing, grows the hold in over 20 game frames, hides it immediately on walking (state 0x66), and restores it when aiming resumes. `hand` is optional. Placement fields are `weap_radius`, `weap_rotation`, `weap_radial_rotation`, `hand_radius`, `hand_rotation`, `hand_radial_rotation`, and `hand_scale` (PX `CWormAnimParams`, with defaults of 1). `static = { weap = -0.1, hand = 0.4 }` fixes angles in multiples of π. `frames` and `anim_speed` animate the weapon sheet. `keep_while_firing = true` retains it in WA's firing poses; `thrown = true` skips the put-away animation. `flash = { sheet = "sprites/flash", out = 30, side = 2, scale = 0.45, frames = 3 }` draws a short additive muzzle flash after a shot. These sheets use the GPU atlas and do not consume WA sprite slots.

`wa.on.turn_start(function(event) ...)` receives `event.worm` / `event.active`. The same fields go to `wa.on.turn_retreat` when weapon use ends and retreat begins, `wa.on.turn_end` when retreat ends and movement stops, and `wa.on.turn_cleanup` after WA clears the worm's active-turn state. They fire in that order; a zero retreat may put all three in one frame. See `mods/examples/hello`. `wa.on.death` fires once per worm with `victim`, current `active`, and optional `attacker`, `attacker_team`, `weapon`, `slot`, and `kind`. `wa.on.hurt` keeps its old fields and also carries those optional attribution fields. Missing attribution is `nil`: delayed stock projectiles expose their team but are never guessed to belong to the currently selected worm/weapon. Compare worms by stable `.id`, not userdata identity.

`a:frame(i)` holds a LuaActor on one frame of its current sheet (zeroes the loop delta). `worm.facing` is read-only (−1 left, +1 right). `cluster = { sprite = "sprites/bits", homing_sprite = "sprites/bits_homing" }` takes pack sheets for the cluster bits and for what homing bits draw while they home (their render timer). `fire_repeat = 5` runs stock FireWeapon that many times per shot, in the same frame (PX’s Real Shotgun: five pellets). `plane = "sprites/plane"` on a strike slot gives the strike its own plane (the strike’s `+0x38`, where the stock jets are 86 and 87). `sprite_overrides = { wsvbd = "sprites/trail", [466] = "sprites/x" }` on `replace` swaps any stock sprite (Gfx.dir name or id 1–799) for a pack sheet for the whole match, as PX’s `SetSpriteOverride` does: every user of that sprite draws it, so only override sprites nothing else in the match needs (PX repurposes the Salvation Army’s `wsv*` frames as trails). `worm_sprites` on `replace` remaps that slot’s worm poses only (`weaponlnk` / `wthrow` and slope variants; on the uzi, minigun, shotgun and handgun also `weaponfire*`, the gun firing, which falls back to the `weaponlnk*` sheet). `ev.damage` on an actor brain is stock blast falloff this tick. Overlaying a mine’s fire (`copy_from = "mine"` plus `on_fire`) keeps placement/retreat and routes the body through the existing projectile wrap. `wep = "x.wep"` on `replace` gives the slot a Project X weapon file’s firing (a PX `.wep` is WA’s weapon table entry behind a 4-byte tag), exclusive with `copy_from`; its name is the default name, explicit params and pack art still win, and a sprite field naming a PX-only sprite keeps the slot’s own (see `hellish_grenade`). `patch = { damage = 70, detonation = 1 }` on `replace` writes named weapon fields after `copy_from` / `wep` laid the base down (legacy `[offset]` keys still work) — the web editor’s readable diff; fire type must stay 0–4, and PX sprite ids keep the slot’s stock art as with `wep`.

`mole_dig_rotation = { moledive = "sprites/dive.png", moledig1 = ..., moledig2 = ..., moledig3 = ... }` replaces the mole strike's digging frames globally for the match, as PX's `SetSpriteOverride` does; any subset of the keys works, and no other sprite is accepted. A fifth key, `mole`, is WA's underwater variant of the dive frame (a diving mole that enters water switches 158 → 663; the dig frames have none). If a pack overrides `moledive` but not `mole`, the dive sheet sinks under PX's sinking tint, `RGB(90, 90, 240)` multiplied in, instead of turning back into WA's mole. The PNG/GIF must live in the pack; the first loaded claim for a frame wins, and every mole in the match uses it.

## Porting from Project X, and worm states

A Project X script is a **behaviour spec, never an implementation spec**. Port what the weapon does, not how PX did it. PX runs on WA 3.6.31, and its weapons are hacks users found by trial and error: its offsets, records and state tricks are not evidence about 3.8.1. (Parking a swimming worm in the bungee state gave PX free movement without fuel; it is not how WormForge should build a swim mode.)

- **Packs do not name or set WA worm states.** Hand a worm between WA and a pack with the engine's verbs: `worm:take` / `worm:release` for a vehicle the pack drives, `worm:carry` / `worm:drop` for pinning a worm to a point, `worm:jetpack_steer` for steering WA's own jet pack. `worm:set_state` is a debugging tool on its way out: a pack must declare `debug_worm_state = true` in its `mod.toml` to call it, and every call is logged. Do not add new uses.
- **Evidence first.** No new raw WA write (worm state, worm field, weapon-table offset) without WA 3.8.1 evidence named in the commit: a state trace excerpt (`wkLua.log` `state ...` lines), or disassembly of `WA.exe`. The known states and their evidence are in `crates/game/src/worm_state.rs`; add to it there, and mark a name resting on one observation with `?`.
- **Reuse before adding.** Before a new verb or engine hook, list which existing verbs and examples you checked (`pooz`, `worm_toss`, `super_drill`, `turret`, the Highlander sections) and why they fall short.
- **Lockstep.** Every write that reaches the simulation runs in a simulation callback, and a replay of a match using it must play to the end without `replay player stopped`.

## Verbs (engine)

If the current `wa.*` surface cannot do it: wrap stock 3.8.1, bind a handle API, show it in one example. Target `i686-pc-windows-msvc`. Wrap, then original — never trap `FireWeapon` / `InitWeaponTable`, never stack VFTs, never grow the 71-slot table. Details: README.

**WA addresses are resolved by signature, never hardcoded.** Function entries, globals and patch sites come from masked byte patterns in `re/Signatures.toml`, matched at startup against the unmodified `WA.exe` on disk (not live memory, so another WormKit module's detours don't break them), and looked up by name: `crate::wa::address("STRIKE_FIRE")`, or `try_address` for an optional one. Hook through `crate::wa::create_hook(address, detour)`: it checks the entry (stock bytes, or a jump another module put there, which it chains through), and a required hook that fails rolls the others back. Don't add a VA to runtime code or as a fallback; the VA constants left in `crates/game/src/offsets.rs` are documentation. Object field offsets (`worm+0x248`) stay constants there: signatures are only for code and global addresses.

To use a new WA function or global, add a `[[locator]]`: `name`; `reference_va` (the Ghidra/objdump VA, documentation and audit only); `section = ".text"`; `pattern`, about 32 bytes from the entry with `??` over branch displacements and relocated absolute operands, which must match exactly once; `derive = "match"` for the match itself, or `"abs32"` / `"rel32"` with `operand` (the operand's byte offset in the pattern) for a global or a call target; `target_section` where the result must land (`.text`, `.data`); and `required = false` for an optional feature, which then disables itself with a logged reason instead of refusing to load. Check it with `WF_WA_EXE=<path to WA.exe> cargo test -p re-catalog --target aarch64-apple-darwin`, which resolves every locator against that executable and compares each with its `reference_va`.

GPU drawing has one hard requirement: WA's **Direct3D 9 (shader)** renderer (`Renderer` = 4 in WA's Options; WA's default where supported). It is what draws GPU sheets (`gpu_prefix`, GPU worm sheets, `sprite_overrides`). On any other renderer, or with another WormKit module hooking the same D3D9 sites (wkFOW), they are not drawn at all: there is no palette fallback, except for sprites WA also holds itself (`sprite_overrides`, and the true-colour copies below), which WA then draws in palette colours.

A pack sheet WA must hold as a real sprite (a weapon body, cluster bits, a strike's plane) goes into WA's 256-colour palette, which a map can fill: its colours then fall onto the map's nearest ones. So by default such a sheet also gets a true-colour copy in the GPU atlas, drawn in its place; WA keeps its palette copy for sizes, frames and phases, and draws it when the copy cannot be (another renderer, or the copies not fitting the atlas, which `wkLua.log` says). `params = { truecolor = false }` keeps the palette draw, for a sheet painted in WA's team-colour entries on purpose. `wkLua.log` names WA's renderer setting at each match and says which of the two it is.

Draw primitives belong in the DLL. Named FX (lightning, fire) belong in Lua. No second renderer. Do not vendor `Resources/` or GPL game-replacement sources. Do not drive-by rename the whole API in the same PR as a pack.

## Lua surface

- `require("lib/shared")` loads `lib/shared.lua` from the pack's own folder: `/`-separated names of letters, digits, `_` and `-`, no extension, never outside the pack (symlinks refused). Each module runs once per match in its own environment: it reads the shared globals (`wa`, the standard libraries, what the entry set) and its own `require`, but its global writes stay private; `require` returns what it returned (`true` for nothing). A require cycle, or requiring the pack's entry, is an error naming the files. Modules travel with the pack (network sync and replays carry every file), so they need nothing declared. The entry chunk's own global reads and writes still go to the shared globals, as before.
- Component bundles (`format_version = 2` in `mod.toml`, see `mods/examples/component_demo`): weapon, scheme and feature components, run only when `[profile]` in `Mods/wormforge.toml` selects them. A component's file only returns data, with `wa` unavailable while it does: a weapon `{ defaults = {...}, install = function(ctx) end }`, a scheme `{ weapons = { [id] = overrides }, install = ... }`, a feature its install function. Weapon data is `ammo { round_start, turn_start { amount, mode = "add" | "replace" }, crate_collect }`, `delay`, `crate { chance_pct, type }`, `ends_turn`, `power`; the scheme's overrides are laid over the weapon's defaults field by field and arrive as `ctx.data` (checked, not yet written into WA's scheme). `install(ctx)` runs in load order (weapons by slot, the scheme, the features) with `wa` bound to the component: `ctx.stock_slot` and `ctx.position` for a weapon (the only slot it may claim), `ctx.weapons` (every placed weapon), `ctx.option(key)` for a feature, `ctx.selected(id)`. The selection joins the modset check; at lobby ready the host freezes it (as the `wormforge.profile` pseudo-pack) and the bundles it uses with the packs, and replays archive them the same way, so peers and playback run the host's selection, not their own settings.
- `wa.log`, `wa.weapons.replace` / `register`, `wa.actors.spawn` / `all` / `kind`
- Actor: `x y vx vy facing owner kind`, `a:gravity` `a:move` `a:advance` `a:look` `a:frame` `a:explode` `a:dig{radius}` `a:despawn` `a:spawn` `a:sound` `a:in_water` `a:on_feet`
- Weapon steps (do not steal MineEntity): `on_place` / `on_proximity` / `on_explode` as a function or `{ spawn = { sprite = false, explode = { damage = 0, id = 40, now = true }, damage_worms = false } }`. Same `spawn` table as `on_fire` / `on_click`. `sprite = false` is invisible (blit id 1023). `explode.now` blasts at spawn. Nested `on_explode` on a spawned actor fires when that actor blasts. Stock `CreateClusters` is not this path yet.
- Worm: `id team alliance ammo_group slot weapon kind visible turn hp x y vx vy facing aim aiming drilling`, `worm:carry` `worm:drop` `worm:take` `worm.taken` `worm:fits` `worm:release` `worm:jetpack_steer` `worm:equip` `worm:ammo` `worm:hurt`. `worm:take{ hide = bool, turn = "run" | "freeze" }` hands the worm to the pack: WA's handler still runs but the worm stays where the pack puts it (`worm.x`/`worm.y`), its move keys and jump are the engine's to consume (read them from `worm.keys` / `wa.world.keys()` before they are cleared), and WA's water leaves it alone; `hide` hides it, `turn = "freeze"` stops the turn timer as `carry` does (default `run`: the turn goes on). `worm:carry(x, y)` moves a taken worm (and keeps the facing the pack gave it). `worm:fits(x, y)` (a read) is WA's own collision test of the worm's shape at (x, y) (0x4FB9D0, as WA's landing check calls it): true when it would touch nothing, for a taken worm with the mask it had before it was taken. A vehicle moving a taken worm keeps it where it fits, or WA takes the land it overlaps for ground once it is released. `worm:release(vx, vy)` gives it back to WA moving at (vx, vy), 16.16, through WA's falling-with-control state (0x7E, the one a closed parachute leaves the worm in): WA flies it and lands it with its own states. `worm:release(vx, vy, { tumble = true })` gives it back out of control instead (0x7F, as after a hit): on land it gets up, in water WA drowns it. Release also ends a `carry`, and on a worm the pack never took it is a launch. The engine lets go of a taken worm by itself at the turn's end (WA's retreat-finished or finish-turn message to the turn's worm, before `wa.on.turn_end` runs; or, with no retreat running, when the turn clock runs out or WA flags the turn ended) (into 0x7E, where it is, its mask as it was when taken) when WA knocks it flying (a hit or a blast: WA's state and speed kept), and when it dies held, whatever killed it (WA's state kept: WA runs a worm's death only once it has come to rest, which a held worm never does); `worm.taken` (read-only) is true until then, so a pack sees the handoff and tidies up. `worm:jetpack_steer(on)` makes WA's jet pack ignore the move keys (no thrust, no fuel burn) so the pack steers it with `vx`/`vy`/`fuel`; WA keeps collisions, the fuel HUD and the landing, and it lapses when the jet pack ends. After an `on_click` fire the engine ends WA's prefire state itself; the pack does not. `worm.drilling` reads WA's stock drill state and is read-only. `worm.aim` (read-only) is the aim WA draws, 0 straight down to 1 straight up (the sweep at +0x270; `facing` gives the side). `worm.aiming` (read-only) is true while WA draws the worm with its weapon out: standing with it or charging a throw. `worm.facing` is writable (WA's turn side). `worm.body_visible = false` hides only the body sprite (Project X's RenderWorm): WA still draws the worm's name, health, jet pack fuel and cursor, which `worm.visible = false` hides too. `worm.fuel` is the jet pack's fuel, 16.16 (0 is unlimited). `worm.shots_fired` / `worm.shots_to_fire` are a repeat-fire weapon's shots (Project X's `nShooted` / `nShoots`; writes from simulation callbacks only): while fired is below to-fire, WA fires again after the weapon's delay, so holding them at 0 and 1 keeps the worm firing, aim live. `worm.gravity` / `worm.wind` are how strongly gravity and wind act on the worm, 16.16 (65536 is WA's normal). `worm.state` names WA's state where it is known (`standing` `prefiring` `punching` `drilling` `teleporting` `jetpacking` `parachuting` `sliding` `bungee` `tumbling`), else nil; `worm.state_id` / `worm.state_label` give the raw number and its debug label (`crates/game/src/worm_state.rs`), for logs only. `worm:set_state("sliding" | "standing" | "bungee" | "tumbling" | "teleporting")` enters one through WA's own SetState, from simulation callbacks only, for packs that declare `debug_worm_state = true`; it is a debugging tool on its way out (see Porting from Project X). `tumbling` (0x7F, once misnamed `sinking`, still accepted) is WA's out-of-control state after a hit: in water it ends in drowning. `worm.collision_mask` is the layers it collides with, a bit per layer (WA's +0x34, Project X's `ColGroup`), writable; bit 22 (0x400000) makes WA's water act on it: without it a worm in the water is neither sunk nor drowned. `worm.keys` is the worm's own move requests `{ up, down, left, right }` (WA's, from lockstep input; `wa.world.keys()` is the whole keyboard state WormForge syncs, Shift (`sprint`) and the digit held (`digit`, 0-9, top row or keypad, else nil) included: in a networked match the keys of the player whose turn it is, the same on every machine, none between turns or on a computer team's turn; offline, this machine's), and `worm:clear_keys()` consumes them before WA's handler sees them (simulation callbacks only).

For a hard vehicle landing with the parachute equipped, `worm:release(vx, vy, { suppress_auto_parachute = true })` lets WA process the impact at full speed instead of reopening the parachute first. The selected slot is restored after each frame.

- Inventory: `wa.inventory.create`, then `get` `set` `add` `remove` `clear` `list` `deal` `transfer` `apply`
- `wa.worms.all` / `nearest`, `wa.crates` / `mines` / `missiles` / `oil` `.all()` (pos + `kind`)
- `wa.land.solid` `trace` `dig{ x, y, radius }` `cut{ x, y, shape = "drill" | "torch", facing, angle }`, `wa.world.sky` `water` `size` `view` `pointer` `keys` `cavern` (`wa.world.cavern()` is WA's own cavern flag for the match; `wa.world.retreat()` is the retreat countdown in ms, 0 until retreat starts; `wa.world.turn_clock()` is the turn clock in ms left, as WA counts it: it stands still while WA waits for everything to settle after a shot, and during a retreat). `wa.world.gravity()` / `wa.world.wind()` are WA's gravity and wind, 16.16 speed per frame (Project X's `Env->Gravity` / `Env->Wind`), before WA scales them by an object's own factors (`worm.gravity` / `worm.wind`); the wind changes each turn. `wa.world.set_gravity(v)` / `wa.world.set_wind(v)` (simulation callbacks only) change them: gravity as the match's gravity (the scheme's, which WA scales by its low-gravity percentage every frame), wind through WA's own wind change (message 0x54), so the clouds and the wind bar follow. Terrain cuts require a simulation callback; coordinates are 16.16, radius is 1..200 pixels. Torch requires facing ±1 and angle in 16.16 from −65536 to 65536.
- `wa.perf.enable{ counter = true, profile = true, packs = false, spikes = false }` (no table: counter and profile) turns on this machine's FPS counter (top right: the live frame rate, the 2 s average, the longest frame of the last 5 s in ms) and profiler (a `perf:` line in `wkLua.log` every 10 s with `sim` `scene` `draw` `present` `hud`, the `lua` time within them, and `other`, then a `perf lua:` line splitting the Lua time by call). Any single Lua call of 5 ms or more is logged as it happens, as a `perf spike:` line with the call, the frame, and Lua's memory around it (a drop means a GC cycle ran in it). `packs = true` with `profile` adds each pack's hook handler time to the `perf lua:` line, and `spikes = true` adds the Lua lines each spike spent its time on; both slow Lua down while on. Presentation only: Lua cannot read a timing back. See `mods/examples/perf`.
- `wa.sound.play`, `wa.on.gravity_before` / `gravity_after` / `missile_frame` / `worm_message` / `hurt` / `turn_start` / `turn_retreat` / `turn_end` / `turn_cleanup` / `death` / `hud`, `wa.hud.line`
- `wa.on.missile_frame(function(m) ... end)` runs for every WA missile each frame (`m.phase` "pre" / "post" around stock). `m.x y vx vy` are writable. `m.weapon` is the stock slot name the missile was fired from, as `worm.weapon` gives it (cluster bits take their parent's; strike bombs and crate bombs have none), `m.collision_mask` is the layers it collides with, as the worm's, and writable. `m.id` identifies the missile: a number counted up per match in the order WA builds missiles, the same on every machine and never reused within a match, so a pack may key its own per-missile state by it (a missile's memory address would be neither). `m.sprite` is the sprite WA draws it with (MissileEntity+0x2EC, a copy of its fire params' sprite made when it was created) and is writable: 0 draws nothing, as Project X hides a missile it draws itself, while the weapon's record, which a thrown weapon's worm posture is picked by, keeps its sprite.
- `wa.weapons.launch{ weapon = "bazooka", owner = worm, x, y, vx = 0, vy = 0, damage, sprite, fuse }` fires a real WA missile from a slot's fire params, as WA's `CreateWeaponProjectile` does and Project X's `new CMissile(...)`: WA flies, draws, trails and explodes it as its own, and it is that slot's missile to every hook (`m.weapon`, `on_explode`). `owner` is the worm it is fired for (its team and worm number); positions and speeds are 16.16. `damage`, `sprite` (stock name or id), `fuse` (ms), `sound` (its flight sound, 0 for none), `explode_into` (`"nothing"`, `"clustlets"` or `"fire"`: what it bursts into, from the record's own cluster params), `countdown` (ms; Project X's `countdownFrom`) and `explode_on_space` (the fire key sets it off in flight) change this missile only, in a copy of the fire params. Simulation callbacks only. It returns the missile's id, the `m.id` of `wa.on.missile_frame`; a missile's `on_explode` event carries its id as `ev.missile`.
- `wa.fire.spawn{ owner = worm, x, y, vx = 0, vy = 0x40000, count = 8, duration = 4000, up_power = 100, damage = 20, damage_scale = 1, knock_scale = 1, tint }` starts one of WA's fires (FireEntity), as WA's Petrol Bomb starts its own (`MissileEntity::CreateFire1`) and Project X's `new CFire(Root->GetObject(TI_FireStore, 0), &desc, 0)`: WA burns, spreads, draws and hurts with it as its own. The fields are Project X's `CFireDesc` (`SpX`/`SpY` as `vx`/`vy`, `Count`, `Duration`, `UpPower`, `Damage`), 16.16 positions; a bare spawn takes the Petrol Bomb's values. `owner` is a worm or actor: its world's fire store is the parent, and a worm's team owns the fire. `duration` must be above 0. `damage_scale` and `knock_scale` (default 1, as WA's) make that fire's hits on worms stronger or weaker: WA's fire hits a worm with message 0x4B, kind 1 (Project X's `M_GUNEXP`), and the engine scales its damage and knockback before WA and `wa.on.hurt` see it, as Project X's Valyrian Fire does. `tint = 0xRRGGBB` draws that fire's flames half their own colours, half the tint (Project X's `SetColorMod` mode 1), from full-colour copies of WA's fire sprites (petrol_1..4, petrol1..6) the engine makes at match start through WA's own frame getter, at the fire's own render-queue depth; without the D3D9 shader renderer WA draws them untinted. The engine forgets a fire's scales and tint as WA frees it. Simulation callbacks only (the constructor draws from WA's RNG). Returns the fire's number in this match.
- `on_fire` on a gun slot (fire type 1, method 2: uzi, minigun, handgun, shotgun) takes every shot WA fires, and WA's bullet is skipped, as Project X's `FireFinal` without `super`; `fire.x`/`fire.y` are the worm's position and `vx`/`vy` are 0 (read `worm.aim` and `facing`). On a projectile slot it replaces the projectile, as before.
- `wa.on.draw(function() ... end)` runs at render time, once per rendered frame (not per sim frame, and differently on each peer): read state and draw, nothing else. `wa.draw.quad{ points = { {x, y} x4 }, color = 0xAARRGGBB | colors = { four }, sprite = "sprites/sheet", frame = 0, blend = "alpha" | "add", depth = 0x10000 }` draws a textured quad (corners in 16.16 world coordinates, clockwise from the one that takes the sheet's top-left; the sheet must be a GPU sheet, e.g. under `gpu_prefix`), what Project X's `AddSpriteQ` draws. `depth` places it among the GPU sprites (actors, pack sheets) as theirs does, as `AddSpriteQ`'s Z plane does: a lower depth is nearer, at an equal depth the quad draws over the sprite, and at or behind terrain (0x180000) terrain hides it. Ribbons take their place the same way. `wa.random` refuses to run there; `wa.draw.random()` gives 0 <= r < 1 for looks only.
- `wa.draw.ribbon{ points = { {x, y, width, color, u}, ... }, sprite, blend = "alpha" | "add", depth }` (inside `wa.on.draw`, 2..256 points) draws one textured strip through the points, as Project X's `pxtexbeam`: `width` is the full width in pixels, `u` runs 0..1 along the strip so the texture does not restart at bends, and each point has one normal averaged from the sections either side, so the strip bends without kinks. The sheet must be a GPU sheet.

These writes are simulation callbacks only.

### Adding terrain

`wa.land.stamp{ sprite = "sprites/sheet", frame = 0, x, y }` adds a registered
pack sheet's frame, centered at the 16.16 position. Simulation callbacks only.
Frames are zero-based and must exist (no wrapping); dimensions must be 1..256
pixels. Source alpha below 128 leaves the land unchanged. Opaque pixels,
including black, become solid. Colours are the nearest of those the terrain
picture already holds, so every machine writes the same pixels; the palette is
never changed. The stamp goes through WA's own girder routine
(Landscape::plot), which clips it and updates collision, the terrain picture,
the soil layer, rollback storage and redraws. Source pixels are retained for
GPU sheets too, independent of drawing and device reset.

`buried = { soften = 2, blend = "dither" }` changes only the pixels that fall
on existing land, so a stamp can look stuck in the ground: a javelin's tip
fades into the earth while its silhouette stays. Each such pixel keeps
`min(d, soften) / soften` of its strength, `d` being its distance in pixels to
the frame's outline (computed once, when the sheet is installed), so the
sprite's thick middle stays whole and its edges fade. `blend = "dither"` keeps
or drops each pixel against a 4x4 ordered-dither pattern anchored to the map;
`"mix"` blends its colour with the land's and takes the nearest terrain colour.
`soften` is 1..32 pixels (default 2), `blend` defaults to `"dither"`. Without
`buried`, the whole frame is drawn over the land.

`object:hit(damage, vx, vy, "projectile")` uses stock projectile impact handling
for mines, crates and oil drums. Omitting the fourth argument keeps the existing
direct-hit behavior. Mines apply their own stock rules for impact and damage.
